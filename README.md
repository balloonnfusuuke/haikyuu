# プレート先端

ホームプレートの捕手側の先端を原点にして、Statcast の一球を Three.js で見るビューアです。球場の形は Blender で作った `stadium.glb` を読みます。ファイルが無いあいだは、同じ寸法の仮球場で開発できます。

## 起動

```bash
npm install
npm run dev
```

ブラウザで http://127.0.0.1:43127 を開きます。

```bash
npm test
```

座標変換と、プレート前端を球が通ることをテストします。

## 座標

変換は `lib/coords.ts` の `statcastToThree` だけです。投球の軌道、到達位置、打球、カメラ、仮球場の寸法は、すべてここ（または同じ式の `statcastToWorld`）を通ります。

入力はフィートです。

- 原点はホームプレートの捕手側の先端、地面
- +x は捕手から見て右（一塁側）
- +y は投手・マウンド方向
- +z は上

メートルにしてから、glTF の +Y up 書き出しと同じ入れ替えをします。Blender の (x, y, z) は Three.js の (x, z, -y) です。

```
three = (xFt * 0.3048, zFt * 0.3048, -yFt * 0.3048)
```

球場を動かしても追いつくよう、実行時の位置は `Marker_PlateTip` と `Marker_Rubber` から作った基底にこの式を載せます。プレートが原点で軸が規定どおりなら、ワールド座標は `statcastToThree` と一致します。モデルの頂点座標はコードに書きません。

Baseball Savant の `plate_x` も、捕手から見て右が正です。右投手のリリースはだいたい負の x（捕手から見て左）です。

`plate_x` と `plate_z` は、プレート前端（先端から 17 インチ = 1.417 フィート）を球が横切る位置です。

## 仮球場と stadium.glb

`public/models/stadium.glb` が無い、または読めないときは、地面、プレート、マウンド、投手板、白線だけの仮球場を出します。ルール上のフィート寸法を `statcastToThree` に通しているので、Blender のモデルと同じ位置関係です。

読み込みは `GLTFLoader` と `DRACOLoader`（デコーダは `public/draco/`）です。Draco 圧縮の glb をそのまま渡せます。

Blender 側の約束:

- 単位はメートル。原点はホームプレートの捕手側の先端、地面の高さ
- +Y がマウンド方向、+X が捕手から見て右（一塁側）、+Z が上
- 書き出しは glTF 標準（+Y up）

オブジェクト名の例: `Field_Dirt`, `Field_Grass`, `Mound`, `HomePlate`, `BattersBox_L`, `BattersBox_R`, `Backstop_Net`, `Wall_Outfield`, `Stand_Infield`, `Roof_Ginsan`, `LightTower_01`〜`06`, `Scoreboard`

目印（Empty）:

| 名前 | 位置 |
| --- | --- |
| `Marker_PlateTip` | 原点 |
| `Marker_Rubber` | 投手板の前縁の中央 |
| `Marker_CatcherCam` | プレートの 2.5 m 後ろ、高さ 1.1 m |
| `Marker_Bases` | 塁の位置 |

読み込んだあと、プレート先端から投手板前縁までの距離を測ります。基準は 18.44 m、許容は ±5 cm です。外れていればコンソールに `console.warn` し、画面左上に赤い警告を出します。合っていれば緑の文字で距離を出します。`Marker_CatcherCam` が無いときは、同じ相対位置を捕手カメラに使い、その旨を画面に出します。

捕手視点の初期位置は `Marker_CatcherCam` です。右打者・左打者・一塁側・三塁側は、プレートと投手板の目印から作った軸に沿った相対位置です。右打者は捕手から見て左（三塁側）の打者席に立ちます。`BattersBox_L` / `BattersBox_R` の L/R も捕手から見た左右です。

距離の警告だけ試すときは、仮球場で `http://127.0.0.1:43127/?shiftRubber=0.2` を開きます。`Marker_Rubber` を 20 cm 遠ざけます。

## 光と小物

環境光は Poly Haven の HDRI です。CC0 の 1k を同梱しています。

- 昼: `public/hdri/day.hdr`（kloofendal_48d_partly_cloudy_puresky）
- ナイター: `public/hdri/night.hdr`（moonlit_golf）

同じファイル名で差し替えられます。昼は空を背景にも使い、ナイターは環境光だけにして背景は夜空にします。影を落とすディレクショナルライトは 1 本です。4096 のシャドウマップはプレートからマウンドまでのバッテリーにだけ掛かる範囲に絞っています。

ボール、バット、ミット、人物は球場とは別ファイルです。無ければ手続きの形で動きます。

| ファイル | 中身 |
| --- | --- |
| `public/models/ball.glb` | 中心が原点。半径が違えば公式球（約 3.7 cm）に合わせる。縫い目付きを想定 |
| `public/models/bat.glb` | グリップ端が原点、+Y が先端、長さ約 0.86 m |
| `public/models/mitt.glb` | 捕球点が原点、正面が +Z |
| `public/models/player.vrm` | 足元が原点、正面が +Z。打者の位置に置く |

球の回転は `release_spin_rate`（rpm）と `spin_axis`（度）です。180° が真のバックスピン、0° が真のトップスピン、90° は捕手から見て右へ曲がります。軸は進行方向に垂直な成分だけで、ジャイロはデータに無いので、報告された軸のまわりに回転数すべてで回します。縫い目は「ボール」視点、速度 0.1x で見えます。

サンプルは右投手のフォーシーム、スライダー、カーブと、右打者のライナーです。加速度は y = 50 ft 地点の Statcast の等加速度モデルで、プレート位置は軌道から求めています。

## 1 球で到達位置を確認する

仮球場のままで確認できます。`stadium.glb` を置いたあとも、目印が合っていれば同じ手順です。

1. `npm run dev` で http://127.0.0.1:43127 を開く。左上に赤い警告が無く、「プレート先端から投手板前縁まで 18.442 m（基準 18.44 m ± 5 cm）」のように許容内であることを見る。コンソールにも同じ文が出る。警告が出るときは `Marker_PlateTip` と `Marker_Rubber` の距離がずれている。
2. 右の球種が「フォーシーム」であることを確認する。この球はストライクゾーンの中（おおよそ plate_x = -0.20 ft、plate_z = 2.41 ft）を通る。
3. 「プレート通過へ」を押す。再生で止めたいときは「通過で止める」をオンにして「再生」を押す。スペースキーでも再生と一時停止ができる。
4. 「到達位置」を見る。データの `plate_x` / `plate_z` と、「ボールの x / z」（画面上のボール中心を、目印の基底でフィートに戻した値）の差が 0.5 cm 未満なら、見出しが「一致」になる。ボールの y はプレート前端の 1.417 ft（17 インチ）になる。
5. 捕手視点のまま、プレート前端の琥珀色のリングの中に白い球があることを見る。リングはデータの到達位置を `statcastToWorld` で置いたもので、球とは別に置いている。視点を「一塁側」に替えても、球は同じリングの中心にいる。ずれていれば、軌道と表示のどちらかが変換を通っていない。
6. 右の図で、白抜きの円がデータの到達位置、赤い点が今のボールです。プレート通過の瞬間は重なる。図の右が正の x、一塁側です。下の白い五角形がプレート、黄枠がストライクゾーンです。
7. 縫い目を見るときは視点を「ボール」にし、速度を 0.1x にして再生する。回転軸の表示は「回転軸」。数値は `release_spin_rate` と `spin_axis` です。

スライダーは一塁側へ外れ、カーブはゾーンの下を通ります。どちらも同じリングの検査ができます。「ライナー」は打球で、落下点まで同じ変換を通ります。プレートの検査は投球で行ってください。
