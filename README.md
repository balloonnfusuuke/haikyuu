# プレート先端

ホームプレートの捕手側の先端を原点にして、Statcast の一球を Three.js で見るビューアです。球場の形は Blender で作った `stadium.glb` を読みます。ファイルが無いあいだは、同じ寸法の仮球場で開発できます。

## 起動

```bash
npm install
python3 -m venv server/.venv
server/.venv/bin/pip install -r server/requirements.txt
server/.venv/bin/uvicorn plate_game.app:app --app-dir server --host 0.0.0.0 --port 43128
```

別のターミナルで画面を起動します。

```bash
npm run dev
```

ブラウザで http://127.0.0.1:43127 を開きます。右のパネルで投手と打者を選び、球種とコースを指定して「投げる」と、1打席が最後まで進みます。球の後ろに球種色の軌跡が付き、等速・1/4・1/10、再生、コマ送り、もう一度でその1球を見返せます。カメラは捕手、中継（投手の後ろ）、一塁側、打球追跡です。振った球はバットがグリップを軸に回り、ファウルとインプレーは実球の初速・角度・落下点（hc_x / hc_y）で飛びます。結果を見てから「次の球」で進みます。インプレーの実球は、打者・球種・半マス以内から乱数で1つ選び、少なければ同じ利き手、それから3人の合算へ広げます。乱数の種は残し、球ごとに番号を進めるので、同じ配球でも結果は変わります。

打者の判断は `server/` の FastAPI です。画面は今の Three.js のままです。Statcast は `data/game/` に保存してあり、起動のたびに取りに行きません。取り直すときだけ `server/.venv/bin/python server/fetch_statcast.py` を実行します（`pybaseball` が必要です）。2025年の公式戦（レギュラーシーズンとポストシーズン）だけを使っています。

```bash
npm test
PYTHONPATH=server server/.venv/bin/python -m unittest server.tests.test_game
```

座標変換と、プレート前端を球が通ることをテストします。Python 側はコース、カウント、同じ種で結果が再現することをテストします。

## 座標

変換は `lib/coords.ts` の `statcastToThree` だけです。投球の軌道、到達位置、打球、カメラ、仮球場の寸法は、すべてここ（または同じ式の `statcastToWorld`）を通ります。

入力はフィートです。

- 原点はホームプレートの捕手側の先端、地面
- +x は捕手から見て右（一塁側）
- +y は投手・マウンド方向
- +z は上

メートルにしてから、glTF の +Y up 書き出しと同じ入れ替えをします。Blender の (x, y, z) は Three.js の (x, z, -y) です。

```
three = (xFt * 0.3048, zFt * 0.3048, -yFt * 0.3048)
```

球場を動かしても追いつくよう、実行時の位置は `Marker_PlateTip` と `Marker_Rubber` から作った基底にこの式を載せます。プレートが原点で軸が規定どおりなら、ワールド座標は `statcastToThree` と一致します。モデルの頂点座標はコードに書きません。

Baseball Savant の `plate_x` も、捕手から見て右が正です。右投手のリリースはだいたい負の x（捕手から見て左）です。

`plate_x` と `plate_z` は、プレート前端（先端から 17 インチ = 1.417 フィート）を球が横切る位置です。

## 仮球場と stadium.glb

`public/models/stadium.glb` が無い、または読めないときは、地面、プレート、マウンド、投手板、白線だけの仮球場を出します。ルール上のフィート寸法を `statcastToThree` に通しているので、Blender のモデルと同じ位置関係です。

読み込みは `GLTFLoader` と `DRACOLoader`（デコーダは `public/draco/`）です。Draco 圧縮の glb をそのまま渡せます。

Blender 側の約束:

- 単位はメートル。原点はホームプレートの捕手側の先端、地面の高さ
- +Y がマウンド方向、+X が捕手から見て右（一塁側）、+Z が上
- 書き出しは glTF 標準（+Y up）

オブジェクト名の例: `Field_Dirt`, `Field_Grass`, `Mound`, `HomePlate`, `BattersBox_L`, `BattersBox_R`, `Backstop_Net`, `Wall_Outfield`, `Stand_Infield`, `Roof_Ginsan`, `LightTower_01`〜`06`, `Scoreboard`

目印（Empty）:

| 名前 | 位置 |
| --- | --- |
| `Marker_PlateTip` | 原点 |
| `Marker_Rubber` | 投手板の前縁の中央 |
| `Marker_CatcherCam` | プレートの 2.5 m 後ろ、高さ 1.1 m |
| `Marker_Bases` | 塁の位置 |

読み込んだあと、プレート先端から投手板前縁までの距離を測ります。基準は 18.44 m、許容は ±5 cm です。外れていればコンソールに `console.warn` し、画面左上に赤い警告を出します。合っていれば緑の文字で距離を出します。`Marker_CatcherCam` が無いときは、同じ相対位置を捕手カメラに使い、その旨を画面に出します。

捕手視点の初期位置は `Marker_CatcherCam` です。ほかにバックネット裏、内野席（一塁側）、外野席、中継（投手の後ろ）、一塁側、打球追跡があります。右打者・左打者・一塁側・三塁側は、プレートと投手板の目印から作った軸に沿った相対位置です。右打者は捕手から見て左（三塁側）の打者席に立ちます。`BattersBox_L` / `BattersBox_R` の L/R も捕手から見た左右です。

カメラを引いて壁・スタンド・バックネット・屋根・スコアボード・バックスクリーンがプレーとの間に入ると、そのメッシュだけ不透明度を下げます。球場の形は変えず、画面の表示だけです。

距離の警告だけ試すときは、仮球場で `http://127.0.0.1:43127/?shiftRubber=0.2` を開きます。`Marker_Rubber` を 20 cm 遠ざけます。

## 光と小物

環境光は Poly Haven の HDRI です。CC0 の 1k を同梱しています。

- 昼: `public/hdri/day.hdr`（kloofendal_48d_partly_cloudy_puresky）
- ナイター: `public/hdri/night.hdr`（moonlit_golf）

同じファイル名で差し替えられます。昼は空を背景にも使い、ナイターは環境光だけにして背景は夜空にします。影を落とすディレクショナルライトは 1 本です。4096 のシャドウマップはプレートからマウンドまでのバッテリーにだけ掛かる範囲に絞っています。トーンマッピングの初期値は AgX で、右のパネルから ACES に比べられます。露出と太陽光は、黒土が黒のまま見える強さに抑えています。

`stadium.glb` の AO は 2 つ目の UV（`uv1`）です。`aoMapIntensity` は 1、トーンマッピングは AgX です。球のテクスチャは異方性フィルタを最大にします。

ボール、バット、ミット、人物は球場とは別ファイルです。無ければ手続きの形で動きます。

| ファイル | 中身 |
| --- | --- |
| `public/models/ball.glb` | 中心が原点。半径が違えば公式球（約 3.7 cm）に合わせる。縫い目付きを想定 |
| `public/models/bat.glb` | Draco。`Marker_GripBottom` と `Marker_GripTop` を手に合わせる。長さや軸はマーカーから取る |
| `public/models/mitt.glb` | Draco。`Marker_Pocket` を到達位置に合わせ、開口はマーカーの +Z を投手へ向ける。捕球でモーフ `Close` |
| `public/models/human_mixamo.glb` | Draco。`mixamorig` の骨と、クリップ `Pitch`・`MixamoPitch`・`MixamoBat`・`MixamoRun`。投手、打者、走者を 1 つずつ複製して置く。投手は `Pitch` のリリースを球の出る時刻に合わせ、打者は右手にバットを持たせて `MixamoBat`、走者は `MixamoRun` を足の進みに合わせて回す。捕手は体を置かず、ミットだけにする。読めないときは下の仮モデル |
| `public/models/player.vrm` | 足元が原点、正面が +Z。打者と捕手の両方に置く。VRoid Studio で書き出した VRM を置ける。ファイルが無いあいだは人型の仮モデル。体はまだ振らず、バットだけが振れる |

球の回転は `release_spin_rate`（rpm）と `spin_axis`（度）です。180° が真のバックスピン、0° が真のトップスピン、90° は捕手から見て右へ曲がります。モデルは +X まわりがフォーシーム、+Y まわりがツーシームに見えるので、`FF` などは +X、`SI` と `FT` は +Y を `spin_axis` に合わせてから回します。ジャイロはデータに無いので、報告された軸のまわりに回転数すべてで回します。

サンプルは 2025-06-15 の Statcast 100球です。右投手と左投手、フォーシーム、スライダー、カーブが入っています。`vx0`・`vy0`・`vz0`・`ax`・`ay`・`az` は y = 50 ft の値で、t = 0 はその面です。リリース位置から初期位置を戻し、y = 17/12 ft を横切る x, z を計算します。右パネルの `plate_x` / `plate_z` は、この計算値ではなく Baseball Savant の記録です。差は計算位置と記録の距離です。この100球では平均 0.120 cm、最大 0.205 cm です。

## 到達位置

「投げる」で飛んでくる球は、選ばれた Statcast の1球です。軌道は y = 50 ft の `vx0`・`vy0`・`vz0`・`ax`・`ay`・`az` だけで、`plate_x`・`plate_z` には合わせていません。琥珀色のリングは、その球の記録された到達位置です。

同梱の 2025-06-15 の 100球では、計算位置と記録の距離は平均 0.120 cm、最大 0.205 cm です。左上の緑の文字は、プレート先端から投手板前縁までの距離です。基準は 18.44 m、許容は ±5 cm です。

視点は画面下のボタンです。捕手、バックネット裏、内野席、外野席、中継、一塁側、打球、右打者、左打者、三塁側、ボールがあります。打球が出ると、捕手・席・中継の視点は場所を動かさず、打った直後に球の少し先へ向きを変えます。右打者・左打者の視点で、この球場のフェンスを越えた本塁打のときだけ、打球を見たまま一塁方向へゆっくり歩き出します。見逃しと空振りは打席を見たままです。次の球が来ると、また元の位置と向きに戻ります。打球とボールの視点だけは、これまでどおりカメラ自体が球に付きます。スペースキーで再生と一時停止が切り替わります。回転軸の表示は画面下の「回転軸」です。

## 1打席

投手は Skubal、Skenes、Yamamoto。打者は Judge、Ohtani、Soto。球種はその投手が実際に投げたものだけ出します。コースは画面のストライクゾーンを押して選びます。内側の 3×3 がストライク、外周はボールです。内角・外角は打者の利き手で呼びます。投げた球の球速・回転・到達と、打球の速度・角度・飛距離は、右上の半透明のカードに出ます。

バットは `Marker_GripBottom` と `Marker_GripTop` を、仮の打者の手に合わせます。左打者は反対の打席で、グリップの向きも左右を反転します。ミットは捕手視点の手前に置き、ポケットの +Z を投手へ向けます。投球中は選んだコースに構え、見逃し・空振り・ボールのときだけ実際の到達位置へ動いて `Marker_Pocket` で受け、その瞬間にモーフ `Close` を閉じます。ファウルとインプレーは捕りません。「ミットを下げる」と「ミットを透かす」は、投球中にゾーンや球を隠しすぎないための切り替えです。

選んだ球種で、マスの中心に近い実在の投球を重み付きで引きます。中心から半マスほどずれていても選ばれます。打者の判断は 2024 年の公式戦から作り、2025 年の成績では測りません。球種・コース・カウントごとのスイング、空振り、ファウル、安打の内訳を、球数が少ないほどリーグ平均へ寄せます。コースは球種より先に残すので、ゾーンの中と外で振り方が分かれます。インプレーの速度と角度と方向は、その打者の実際の打球から選びます。結果は MLB の記録ではなく、この甲子園のフェンスと定位置の守備で決めます。フライの飛距離が壁の高さを越えていれば本塁打、届かなければ捕球か安打です。MLB で本塁打でも、この壁を越えなければ本塁打になりません。ファウルラインの外はファウルで、ファウルポールより外に出た球は本塁打になりません。ライン上とポールに当たった球はフェアです。ゴロは内野の穴を抜けたときだけ安打で、マウンドの前で止まった球は投手か捕手が取ります。壁に当たった球は二塁打、深い角で外野が遅れたときだけ三塁打です。シフト、失策、併殺はまだありません。同じ球種・同じコースが続くと打ちやすくなる補正は「連続球の補正」で、初期値は 0.06 です。乱数の種を固定すると、同じ配球は同じ結果になります。

「1イニング」は、打順 3 人で 3 アウトまで守ります。四球は押し出し、安打は塁数だけ走者を進めます。終わると「記録」から打席ごとの結果と配球を振り返れます。

2024 年で作った判断と 2025 年の実際は、「記録」を開くと出ます。比べるのはスイング率、空振り率、三振率、四球率、ゴロ・ライナー・フライ、安打・長打・本塁打、それに 0-0、0-2、3-2 のスイング率です。各項目の横に、2024 年の成績をそのまま 2025 年に当てた差を並べます。AI の差がこれと同じくらいなら、ずれは選手の変化です。空振りは球種と、ゾーンの内と外で残します。AI は 2,000 打席、種は 7 です。2024 年が 800 球に満たない打者は、試合日の前半と後半に分けます。
